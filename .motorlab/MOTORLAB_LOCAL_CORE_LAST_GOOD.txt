LOCAL FALLBACK CONTRACT
- First user-visible line: ⚙️ MotorLab attivo
- Reconcile Project Continuity with newer live evidence before choosing a work starting point.
- Preserve native project engines/lifecycle state.
- Before every NEW write-capable application/project modification, initial mutation wording is intent only; perform read-only preparation, show pre-change report, then wait for Bruno approval.
- Apply Change Compatibility Guard and single-writer before writes.
- Eligible LAB work uses risk-scaled Fast Iteration/No-Spin; HIGH-risk and CANDIDATA/MADRE retain full gates.


FOUR PILLARS + ADAPTIVE VELOCITY - R21+
- Four permanent objectives: engine efficiency, automation/programming facilitation, final artifact quality, execution speed.
- Execution speed is the primary optimization priority; TTTA is the primary comparable performance KPI.
- Hard safety/correctness/security/data-integrity/signing/package/approval/lifecycle/project-native constraints still win.
- Complexity must pay rent: prefer on-demand/reused/merged mechanisms over always-on overhead.
- Eligible non-trivial work is decomposed into a dependency DAG; critical-path tasks receive priority.
- Independent tasks start when their own prerequisites are ready; do not impose global barriers without a dependency reason.
- Runner fan-out is adaptive; one runner is preferred when coordination overhead exceeds expected savings.
- Parallel writes require disjoint isolated scopes; one integration lane owns final artifact state.
- Converge compatible outputs continuously and return corrections only to affected scopes.
- Bounded speculative alternatives are allowed only when isolated, safe and likely to beat serial trial without hidden paid/quota abuse.
- Prefer incremental inspection/test/build/cache reuse; invalidate only affected surfaces when evidence permits.
- Learn from verified errors, Root Cause, searches/research, timings, build/cache/provider behavior, compatibility conflicts, recovery and successful/failed strategies.
- Lessons are bounded, evidence-backed, context/invalidation aware, advisory only and never replace current Git/source/provider truth or approval.


R22+ OPERATIONAL EXECUTION FABRIC
- Velocity remains the only scheduler; Execution Fabric is its runtime dispatcher.
- Use DIRECT_FAST for atomic deterministic work when fan-out overhead is not justified.
- For eligible non-trivial work, maintain READY/RUNNING/COMPLETED state and dispatch compatible READY nodes immediately.
- Batch independent read/tool operations in the same host cycle where supported.
- Durable independent nodes may overlap through Background Execution.
- Never wait for unrelated runners merely to reach a global barrier.
- Same-scope writers never overlap; isolated writes still enter final state through one integration lane.
- Correction relay reworks only affected scopes and preserves valid completed work.
- Substantial work records observed execution mode, peak concurrency, critical path, overlap evidence and host limitation.
- PARALLEL_OBSERVED requires real evidence; installed capability is not proof.
- When useful concurrency is impossible because of the host, report SERIAL_HOST_LIMITED.
- Status groups COMPLETATI INSIEME / IN CORSO INSIEME / SBLOCCATI / CRITICAL PATH instead of serial narration.
- Reference executor behavior is defined by central MOTORLAB_EXECUTION_FABRIC_V1.txt and templates/execution/motorlab_execution_fabric.mjs when the local executor can host it.


R23+ INCREMENTAL DYNAMIC EXECUTION
- Before starting a runner, check whether valid reuse can eliminate the task.
- Cache/result reuse is content/input/toolchain/policy aware and non-authoritative.
- Recompute only invalidated deltas when dependency evidence permits.
- After work elimination, prioritize remaining critical-path nodes before non-blocking branches.
- The active DAG may grow from verified discoveries without restarting completed valid work.
- Start FAST LINE; escalate to MINI TREE/FULL DYNAMIC GRAPH only when branching pays for itself.
- Prune pending obsolete/dominated nodes immediately when safe; never prune mandatory safety/lifecycle verification.
- Material events feed the existing operational event memory; never store chain-of-thought.
- Defer large intermediate materialization until downstream use, verification or delivery requires it.
- Bounded speculative racing is reserved for critical uncertainty, not as a substitute for cache/incrementality.
- Proof should distinguish work avoided, work reduced, work parallelized and serial critical-path work.

ARTIFACT-FIRST ROOT CAUSE - R15+
- When Bruno expects an APK/ZIP/testable artifact for an approved defect/regression, artifact delivery is the default critical path.
- Preferred order: repair -> risk-appropriate verify -> artifact -> deliver -> causal/prevention follow-up -> definitive closure.
- Safely deferrable causal work goes to POST_ARTIFACT_ROOT_CAUSE_QUEUE and must remain durably pending.
- Root Cause Closure remains mandatory; ordering changes, obligation does not.
- Non-deferrable safety/security/signing/data-integrity/unreliable-build/high-risk causes remain before artifact delivery when needed to trust the artifact.
- After delivery, preserve exact artifact/ref/checksum while Bruno tests it; later prevention builds are distinct follow-up LAB/ref/artifacts.
- `Artefatto: 100%` may coexist with `Progresso MotorLab complessivo: <100%` while causal items remain.
- Do not use ✅ Problema risolto or 💯 Conclusione definitiva while mandatory causal work is pending.
- Several deferrable defects encountered on the way to one artifact must not force serial full causal archaeology before packaging.

R16 AUTHORITY / PERSISTENT STATE
- GitHub is durable technical authority.
- D1 is live operational authority when connected and reconciled.
- KV is reconstructible cache only and must never contain unique-only critical state.
- One MOTORLAB_OPERATION_ID correlates one logical operation across checkpoints, artifacts, diagnostics and projections.
- Optional service loss must not make MotorLab unusable.
- Never claim provider/plugin integration is live until the connection/resources are verified.
- MOTORLAB_SERVICE_INTEGRATION_STATUS_V1.txt tracks CORE_READY vs real connection/resource/project adoption.

R16 OBSERVABILITY / KNOWLEDGE ROUTING

FOUNDATIONAL CHANGE COMPATIBILITY PILLAR - R19+
- Mandatory before every write-capable MotorLab/project change.
- Inspect authoritative current state for existing equivalent/overlapping rules/functions/paths.
- ONE RESPONSIBILITY = ONE ACTIVE COORDINATOR.
- Reuse/extend/merge the responsible mechanism; explicitly supersede obsolete/conflicting paths.
- Never accumulate avoidable duplicate writers/resolvers/caches/state machines/UI-domain decisions for one responsibility.
- Fast paths, Velocity, automation, restore, migration and optimization cannot bypass this pillar.

PAIRED SAFETY LAB - R18+
- Every verified LAB NN aggiornamento also produces LAB di sicurezza NN from the same functional source state.
- Safety uses a different package/family and unique test-only signing certificate.
- Safety is immutable and may seed a NEW active update family if the current family later corrupts.
- Safety is not CANDIDATA and cannot promote directly to MADRE.

ANDROID UPDATE FAMILY - R17+
- When update-family mode is active, later LAB aggiornamento builds keep one stable applicationId + signing certificate and increase versionCode.
- Bruno-facing revision names are LAB NN aggiornamento while internal family identity stays stable.
- LAB -> CANDIDATA creates a new immutable Android family from the approved method/state; it does not convert or mutate LAB.
- Approved CANDIDATA -> MADRE promotes the same candidate source/family identity according to project signing policy.
- A LAB test key must never silently become a production/MADRE key.

POLLICINO CONTINUITY - R20+
- Pollicino remains external control-plane infrastructure; never inject continuity breadcrumbs into application/domain code.
- Supported persistent/queryable executors publish real liveness plus progress fingerprint evidence.
- Watchdog owns stall/loop classification; Resume Recovery owns continuation.
- Controlled ends publish a terminal seal.
- Missing supported liveness without a seal triggers external read-only pre-reconciliation and RESUME_READY preparation before a later `continua` when the durable sentinel is available.
- Opaque normal ChatGPT thinking is not a trustworthy ping target unless the host exposes a real side-channel.
- Long risky phases should use observable persistent execution when possible; otherwise use bounded checkpoints.
- Supported Codex satellites install the external `.codex/hooks/motorlab_pollicino.py` sidecar adapter and lifecycle hooks when safe; the adapter is not application code.
- Adopted private-project satellites may self-enroll without a long-lived secret when D1 explicitly marks POLLICINO_SOURCE_PROOF_ENABLED and the local Git HEAD matches the registered project/active-operation SHA; the Worker then returns only an ephemeral session token.
- Because project operational heads are mutable, adopted private satellites also publish `POLLICINO_PROOF_HEAD=<adopted-git-sha>` inside the D1 satellite-state string; this stable proof is preferred until the next verified satellite adoption.
- The same adopted proof is persisted locally in `.motorlab/MOTORLAB_SYNC_STATE.txt` (and optionally the project hook); the Codex sidecar uses it before mutable Git HEAD. Metadata-only commits do not rotate it.
- Alive-but-stalled evidence may precompute `READY_STALL_SUSPECTED`; resumed progress supersedes it.
